# 用户管理系统 + 组长能力扩展（含死斗押金"每日即退"模型重构）实施计划

## 一、经济模型重构（Q4 答复的落地，动钱的部分，请重点审）

### 新规则：每日即退
- 死斗凭证**审核通过当天**，成员立即收到当日份额退款 `floor(押金 / T)`（新钱包流水类型 `5: 每日退还`），`duel_member.refunded` 累计已退金额
- **组长移除成员（进行中）**：设已过天数 E（含当天）、已确认打卡 D、已退 R：
  - 移除退款 = `押金 × (T − E) / T`（你给的公式：剩余天数比例）→ 立即退还
  - 罚没 = `押金 − R − 移除退款`（即缺勤天数的份额）→ 记入 `duel.removed_pool`，最终结算按剩余成员确认天数占比分配
  - 成员标记 `已移除`（新状态 4），影子计划下架
- **最终结算（剩余成员）**：每人 `end_refund = floor(押金 × D / T) − refunded`（补齐含舍入尾差）；罚没 = `押金 − refunded − end_refund`；奖池 = Σ成员罚没 + removed_pool → 按剩余成员天数占比逐笔分配（沿用方案一）
- 招募中移除 = 全额退款（等同退出，无天数消耗）
- **示例（T=7，押金 100，每日退 floor(100/7)=14）**：成员第 3 天被移除、确认 2 天、已退 28 → 移除退款 = 100×4/7 = 57 → 罚没 = 100−28−57 = 15（缺 1 天的份额）入池分给剩余成员

### 代码落点
- `SettlementCalculator` 抽出 `splitByDays(forfeit, days 列表)` 静态方法（移除分配与最终分配共用），单测覆盖
- `duel_member` 加 `refunded int`；`duel` 加 `removed_pool int`；钱包流水类型加 `5: 每日退还`
- `DuelSettlementService.dailyRefund(duel, member)`：审核通过分支调用；最终结算改造为新口径（跳过已移除成员、并入 removed_pool）

## 二、管理端用户 CRUD（管理员）

- **增** `POST /admin/user`：账号 + 昵称 + 初始密码（BCrypt）+ 赠 1000 喵币（与注册一致）
- **查** `GET /admin/user/{id}`：单用户详情（现有分页保留）
- **改** `PUT /admin/user/{id}`：昵称 / 头像 / 角色（user↔admin，禁改 ban）/ 密码重置；全部操作后逐出登录态缓存
- **删** `DELETE /admin/{id}`：护栏①不能删自己与其他 admin（先降级）；②名下存在招募中/进行中死斗成员身份（含押金）→ 拒绝"先处理死斗"；③逻辑删除 + 账号归档改名 `{账号}#del{id}` 释放原账号名；逐出全部相关缓存

## 三、组长能力扩展

- **移除成员** `POST /duel/{id}/members/{targetUserId}/remove`：仅组长；招募中=全额退；进行中=按第一节即时结算；不可移除自己（组长）与已退出成员；移除后逐出聚合缓存
- **申请制加入**：创建死斗新增 `joinMode`（0 自由=默认 / 1 审批）。审批模式：`POST /duel/{id}/apply` 提交申请（招募中、不扣押金、不可重复待审）；`GET /duel/{id}/applications` 组长看待审；`POST /duel/{id}/applications/{requestId}/review`（approve 时才扣押金，**余额不足自动拒绝**；reject 留痕）。新表 `duel_join_request`（duel_id、user_id、status 0待审/1通过/2拒绝、审核备注/时间）。开赛时待审申请**自动拒绝**
- **让渡组长** `POST /duel/{id}/transfer/{targetUserId}`：仅组长；目标须为正式成员（非退出）；招募中与进行中均可；即时生效，原组长降为普通成员，全部组长权限随 `leader_id` 转移
- 审核打卡：已完成（沿用）

## 四、数据模型变更汇总

- `duel`：+`join_mode tinyint`、+`removed_pool int`
- `duel_member`：+`refunded int`；状态枚举加 `4:已移除`
- 新表 `duel_join_request`
- `user`：无表变更（管理端只操作现有列）

## 五、冒烟计划（此功能正常测试）

1. 每日即退：审批通过一次 → 钱包 +floor(押金/T)，`refunded` 累计
2. 移除成员（进行中）：退款 = 押金×剩余天数/T 数值断言，罚没入池
3. 最终结算：含 removed_pool 的新口径逐人断言（钱包余额 + 流水 `balance_after` 对账）
4. 管理端：建号/改密/删人护栏（有押金拒删/删后原账号名可重新注册）/封禁保留
5. 申请制：apply → approve（不足额自动拒）→ reject 留痕 → 开赛自动拒
6. 让渡：转移后原组长失去审核权、新组长获得
7. `SettlementCalculator` 新增/调整单测

## 六、实现顺序

常量与表结构 → 钱包每日退还 + 结算新口径（含单测）→ 组长移除/让渡 → 申请制 → 管理端 CRUD → 冒烟 → 提交（实现后按惯例归档文档）

## 七、明确不做

管理员删除在线会话强踢（缓存 5 分钟窗口内自然过期）、死斗转让给非成员、申请超时自动处理、移除成员的申诉
