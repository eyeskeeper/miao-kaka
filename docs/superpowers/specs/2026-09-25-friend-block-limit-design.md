# 好友系统补全（上限 500 / 拉黑 / 点赞通知）设计文档

- 日期：2026-09-25
- 状态：已实现并冒烟通过
- 关联：2026-09-24-friend-system-design.md（好友系统）

## 一、口径定版（拷问结论）

1. **好友上限 500**：`GameConstants.FRIEND_MAX = 500`，好友数=自己方向 status=1 行数；发起申请时双向检查（我方满员不可发起、对方满员直接拦截）；同意时防御性再查双方；存量好友不清理
2. **拉黑 = 解除好友 + 封锁**（`user_block` 表，unique uk_blocker_blocked）：删除双向好友行 + 清理对方→我的待审申请（防同意绕过）+ 写黑名单行；**静默不通知对方**；四路封锁：搜索隐身（双向）、申请拦截（对被拉黑者文案模糊"无法添加该用户"）、围观/点赞走既有 isFriend 拦截（删友后天然失效）；解除拉黑后对方可重新申请
3. **点赞通知**：`NotificationConstant.TYPE_LIKE = 6`；首次点赞成功 → 被赞者通知「"昵称" 赞了你的打卡，小鱼干 +1」（ref_id=recordId）；重复点赞被唯一键拦截不产生通知；feed 内点赞数/已赞态保持（feed 内可见）

## 二、接口增量（/friend）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/{friendUserId}/block` | 拉黑（陌生人也可拉黑，防骚扰） |
| DELETE | `/{friendUserId}/block` | 解除拉黑 |
| GET | `/blocked` | 黑名单列表 |
| `search` | 加 viewerId | 黑名单双向过滤（互相隐身） |

## 三、冒烟结果

| # | 用例 | 结果 |
| --- | --- | --- |
| 1 | 上限：SQL 造满 500 → 申请「对方好友数已达上限」；释放 1 名额后申请+同意成功 | ✓ |
| 2 | 拉黑：双向好友行删除、黑名单写入、对方待审申请清理 | ✓ |
| 3 | 四路封锁：搜索「用户不存在」/ 申请「无法添加该用户」/ 围观「仅好友可以围观」/ 点赞「仅好友可以点赞」 | ✓ |
| 4 | 黑名单列表准确；解除后可重新申请+同意恢复双向好友 | ✓ |
| 5 | 点赞通知 type=6 首次触达（ref=recordId）；重复点赞无新通知 | ✓ |
