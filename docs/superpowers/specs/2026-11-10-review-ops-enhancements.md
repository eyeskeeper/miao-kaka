# 审核运营补强（派单/举报推送 + 解散转个人计划 + 罚没退还 + 误判计数）

> 归档日期：2026-11-10。后端 f092ce0；前端 d3ae4f0。
> 兑现 2026-11-08 审核改版与 2026-11-09 上诉举报设计中"明确不做"清单里的五项。

## 一、互审派单到达推送（type10）
提交凭证即通知派单审核员："待你审核的凭证——xx 提交了今日打卡凭证，今日由你审核；待审超 24 小时将自动通过"。审核员不再需要主动进详情发现派单。

## 二、举报 admin 实时推送（type11）
举报落库即遍历全体 admin（user_role='admin' 未删除）逐一通知"收到死斗举报，请进管理后台处理"。后台页签仍保留（推送是入口，处理在后台）。

## 三、解散后组长影子计划转个人计划
- `dissolveRunningDuel` 不再 `removeById` 组长影子计划：planSource→个人、**显式 set duelId=null**（updateById 忽略 null 字段的坑）、boss_killed 继承共享击杀数（按个人配额封顶）
- 猫的 BOSS 从共享血量（×成员数）按个人曲线重置为第 killed+1 只满血（60+20×killed），换新名字；猫本体、连击、任务清单、10min 模式全部保留，转完即可继续个人打卡（已实测）
- 解散通知文案加"你的计划已转为个人计划，猫猫保留"

## 四、removed_pool 按额退还被移除成员
- `duel_member.confiscated`（新列）留痕每次移除的罚没额；移除文案改"缺勤份额暂扣（小组解散时退还）"
- 小组解散时：Σconfiscated>0 则按额退款（前 n-1 人按比例截断、末位拿剩余兜底防超发），`removed_pool` 扣减至剩余；老数据（无留痕）对应份额与整数尾差沉没
- 正常结算口径不变：removed_pool 仍全额并入奖池分给留下成员（组长吞池漏洞的防线保留——退还只发生在"没有留下成员"的解散场景）

## 五、误判计数公示
- `check_in_evidence.overturned`（新列）：改判（组长仲裁/admin 终裁/超时自动）置 1
- 改判不再覆盖 `reviewer_id`——原判人永久留痕（AI 免审/超时通过的驳回不存在，REJECTED 的 reviewer 恒为人工原判人）
- `DuelVO.MemberVO +misjudgeCount`：同局 overturned 凭证按 reviewer 分组计数（实时查询，改判处逐出聚合缓存）
- 前端：死斗详情成员行误判>0 显示红色「⚠误判N」；审核记录"⚠ 已被改判"条目的审核人即误判者（原判人保留后自动成立）
- 经济处罚仍为零（用户定版不变），误判只有声誉公示

## 冒烟结论（全部通过）
- 派单通知：互审局 A 提交 → 派单员 82 收 type10"待你审核的凭证" ✓
- 误判链路：驳回→上诉→组长改判 → evidence overturned=1/reviewer 保留 82；成员行 (82,1)/(83,0)；history overturned=True 且审核人=原判人 ✓
- 解散转个人：移除至剩组长 → plan_source=0、duel_id IS NULL、is_delete=0、boss 继承；转完个人打卡正常（事件结算走个人 BOSS）✓（含修复：updateById 忽略 null 需显式 wrapper set）
- 罚没退还：confiscated=1 留痕；解散时 A 收到 1 喵币"小组解散，退还你被移除时的罚没份额"，removed_pool 归 0 ✓
- admin 推送：组长局驳回→举报 → admin 4/79 双收 type11 ✓
