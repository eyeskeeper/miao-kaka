# 死斗每日缺卡分成设计（次日打卡即领 + 审核SLA当日化 + 改判组长垫付扣回）

> 归档日期：2026-11-10。后端 260c2a1；前端 6c31045。

## 一、每日打卡到账结构（同事务两笔）
1. **当日份额**：`押金/T`（既有 dailyRefund 不变，驳回可追回）
2. **昨日缺卡分成**：昨日缺卡者的当日份额之和 ÷ 昨日有效打卡人数，**按人头均分**（整除截断，尾差归结算池）
   - 昨日缺卡者 = 在册且昨日无提交记录 ∪ 昨日凭证已驳回
   - 领取资格 = 昨日有效打卡（有记录且凭证非驳回）+ 今日打卡 + 在册；**昨日缺卡今日回补者不领**（罚没不追溯）
   - 第一天无池（昨日 < startDate 天然成立）；组队局 deposit=0 池恒 0

## 二、审核 SLA 当日化（池计算的稳定前提）
- 超时自动通过从"24 小时"改为"**当日未审完**"：每小时任务清 `create_time < 今日 00:00` 的 pending——任何凭证活不过提交当天
- 由此昨日凭证次日只可能是 通过/驳回 两态，**昨日名单不可变**：每日池惰性计算（次日首次打卡触发）无并发时序问题；次日驳回昨日凭证会被"已审过"拦截
- 驳回时序口径：当日驳回的进次日池；SLA 下不存在晚驳回（要么当日驳回要么已自动通过）

## 三、改判组长垫付扣回
- 改判通过（组长仲裁/admin 终裁/超时自动改判）补当日份额时，若 `凭证当日驳回 && 次日该局有打卡`（份额已随每日池分走）→ **从组长钱包扣回等额**（type9 流水、允许负余额、type12 通知、`daily_shared_out` 等额回冲）
- 组长对审核质量负总责，四条改判路径统一（自审误判/仲裁失职/双误判/不作为）；零经济处罚定版不变（原审核成员仍不罚钱）
- 最后一天凭证无次日，其改判缺口不存在（结算后本就不可改判）

## 四、结算重构（防超发）
- `duel.daily_shared_out`：每次分成领取累计本人实发额（原子自增；改判扣回时等额回冲）
- **最后一天池**：结算时（autoApprovePending 后）按 endDate 出勤计算，均分给最后一天有效打卡者，`dailyShare` 入账 + type13 通知（无次日打卡通道，通知即凭证）
- 总结算池 = max(0, Σ罚没 + removed_pool − daily_shared_out − 最后一天已发)，负值截断 + 告警日志（人工对账防线）

## 五、流水与通知
- COIN_TX：8=每日缺卡分成（正额收益，与押金返还是两条流水）、9=误判垫付扣回（负额）
- 通知：12=误判垫付扣回（→组长，含金额与凭证日期）、13=最后一天缺卡分成（→最后一天打卡者）
- CheckInResultVO：分成金额并入 `coinReward`，eventDesc 追加"昨日缺卡分成 +X 喵币已到账"

## 六、冒烟结论
- 每日分成（局41，100/7天=14/日）：昨日 L/A 出勤 B 缺 → 今日 A 打卡领 7（coinReward=7+文案+type8 流水）、L 领 7、B 回卡不领 ✓；修复一处记账 bug（原按整池×人数记账导致重复累计，改为按本人实发额）
- 改判扣回（局41）：B 凭证当日驳回→次日池已发→上诉改判 → L 被扣 14（type9+type12）+shared_out 14→0 回冲、B 补回 14 ✓
- 最后一天池+总账（局44，end=昨日）：结算时 L/A 各领 7（type8"最后一天 1 人缺卡"+type13）；总账：系统收 300=付出 300（L/A 各 14退+7分成+129奖池，B 全罚没）**精确闭环** ✓（另发现一处冒烟数据陷阱：record 状态未置 NORMAL 会导致确认天数 0 全沉没——造数据须完整）
- SLA 零点任务：造昨日 pending 待 00:00 整点任务验证（结果补录）

## 七、边界与明确不做
- 昨日 pending（当日未审完）按打卡计（宽容口径，与自动通过一致）
- 驳回不追回昨日分成（既得收益）；死斗局内无补卡通道
- 不做：跨局累计分成、按押金比例分（本局同押金下等价于均分）、分成实时推送通知（打卡返回文案即告知）
