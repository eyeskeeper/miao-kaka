# 审核改版设计（组长审核 / 组内互审 + AI 预审开关 + 仅剩一人自动解散）

> 归档日期：2026-11-08。后端 faa71ab（清退遗留表 c352a9f），前端见前端仓库提交。
> 适用范围：押金死斗（mode=0）与组队打卡（mode=1）共用同一凭证审核链路。

## 一、建局配置

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `duel.review_mode` | 0=组长审核（存量默认）/ 1=组内互审 | 招募期组长可改（`PUT /duel/{id}`），开赛后锁定 |
| `duel.ai_review` | 0=关（默认，存量局同样关）/ 1=开 | 开启后 AI 建议通过→直接免人工终审；建议驳回→转人工；AI 服务不可用→转人工不阻塞 |

## 二、互审派单：修正版错位环

- 在册成员（含组长）按 `user_id` 升序编号 `0..N-1`；`d = DAYS.between(startDate, 提交日)`
- 当日偏移 `k = d % (N-1) + 1`（恒落在 `1..N-1`），审核员编号 `r = (提交者编号 i + k) % N`
- **永不自审**：`r == i` 等价于 `k ≡ 0 (mod N)`，而 `0 < k < N` 不可能成立
- 均衡性：每天全员同一偏移构成双射——每人恰审一份、被审一份；每 N-1 天与其余每位成员各轮一次
- 两人局退化为固定互审（k 恒 1）；单人局不存在（进行中仅剩 1 人即解散）
- 派单**提交时算定**写入 `check_in_evidence.assignee_id`（跨天不漂移）；审核员被移除→其在途 pending 按剩余成员以各自提交日重算重派（`DuelBattleService.reassignPending`）

> 为什么不是用户原始公式 `(d+i)%N`：`d` 为 N 倍数时会出全员自审日；`(d+i+1)%N` 也只是把自审日挪后。把偏移限制在 `1..N-1` 才彻底消除。

## 三、审核流程

1. 提交凭证（`POST /duel/{id}/check_in`）：互审局当场算定 assignee；当日奖励照旧即发
2. AI 预审（`ai_review=1` 才消费）：`ai_suggestion=0` → 自动终审通过（备注"AI 预审通过：理由"，reviewer_id 置空），返回完整事件结算；`=1` → 留 pending 转人工
3. 人工审核（`POST /duel/{id}/review`）：
   - 组长审核局：仅组长；组长本人凭证自审并公示（`is_self_review=1`）
   - 互审局：仅 `assignee_id` 本人（组长不可代审）；组长凭证同样被派单成员审
4. 列表与公示：
   - `GET /review/pending?scope=mine`（默认）：互审局每位成员看"派给我的"；组长审核局仅组长可调（全量）
   - `GET /review/pending?scope=all`：仅互审局组长，全队只读（条目带 `assigneeName`，无按钮）
   - `GET /review/history`：组内在册成员可见最近 50 条通过/驳回记录（审核人/自审标记/派单人/理由/AI 建议）
5. 驳回必填备注；驳回追回当日奖励（现状不变）

## 四、兜底规则

- **超时自动通过**：进行中局 pending 超 24h → 每小时定时（`DuelScheduler` 整点）条件更新抢占后自动通过 + 事件结算；两种审核模式一致
- 被移除成员本人的在途 pending：移除时即时收口（置通过、记录置正常，不走猫事件结算——影子计划即将下架无宿主）
- 死斗结束自动通过（既有宽容条款，保留）

## 五、进行中仅剩一人 → 自动解散

- 触发：进行中组长移除成员后在册 ≤1 人（必为组长；招募期不触发；两种玩法一致）
- 顺序要点：解散须发生在被移除者影子计划下架**之前**（待审凭证结算沿其计划）
- 押金局：组长退 `押金 − 已按天退还`；`removed_pool` **不分配**（系统沉没）——组长无法靠移光成员吞掉他人罚没份额
- 组队局：无押金段，其余一致
- 共同动作：待审全过 → 组长落定 QUIT、影子计划下架 → 弹劾终止 → `status=DISBANDED`、`memberCount=0` → 站内通知（`TYPE_DUEL_DISBANDED=7`）
- 前端：移除倒数第二人时强确认弹窗（"解散并移除"）
