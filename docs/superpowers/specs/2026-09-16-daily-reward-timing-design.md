# 喵卡卡 · 死斗当日奖励时序改造（打卡即发、驳回追回）设计文档

日期：2026-09-16
状态：已实现并通过冒烟（提交 `0b814ac`）
前置：押金"每日即退"模型（`2026-09-15-admin-leader-economy-design.md`）

## 1. 需求

修改死斗成员收到当日份额退款的时序，用户给定三步流程：

1. 用户打卡时**立刻**获得当日奖励（原来要等审核通过才发）
2. 凭证进入审核状态
3. 审核通过 → 不做处理（奖励已发）；**不通过 → 追回当日奖励**

动机：激励时序前移——用户一提交就能看到奖励到账，感知更强；驳回只是追回，不是"没拿到"。

## 2. 时序变更

| 时点 | 原模型 | 新模型 |
|---|---|---|
| 打卡提交 | 仅入库凭证（待审核态），无奖励 | **立即发放当日份额 `floor(押金/T)`**，与记录/凭证同事务 |
| 审核通过 | 当日此刻发放当日份额 + 事件结算 | **不追加处理**（奖励已发）+ 事件结算 |
| 审核驳回 | 无追回机制（当日未发放） | **追回当日份额**（新流水类型 `6: 凭证驳回追回`），`duel_member.refunded` 同步回落 |
| 结束自动通过 | 结算跳过 | 奖励已在打卡时发放，自动通过仅置记录状态，无需补发 |

## 3. 实现要点

- 发放移入 `DuelBattleServiceImpl.checkIn` 的事务内（记录 + 凭证 + 当日奖励原子化）；AI 预审仍在事务外
- **追回允许余额临时为负**：用户可能在审核窗口内把奖励花掉，无条件扣减（`miao_coins = miao_coins − 份额`）+ 流水记录，保证驳回经济学永远成立，不因用户消费而逃单
- `clawbackDaily` 对 `refunded` 做**净额回落**（`refunded −= 追回额`，下限 0）：最终结算公式 `end_refund = floor(押金×D/T) − refunded` 中 D 不含被驳回天，refunded 也必须不含，否则会少付
- 驳回同时逐出死斗聚合缓存（确认天数已变）
- 被驳回当日记录保持 `status=2 异常`，当日唯一键阻止重复补交（缺卡口径不变）
